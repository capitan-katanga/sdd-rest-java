# Javadoc Tag Reference (JEP 467 Markdown Form)

Quick reference for the five Javadoc tags this skill uses, plus the class-level summary/description split. **Use JEP 467 `///` Markdown Javadoc** on the public API surface. **Never** use plain `/** ... */` Javadoc on documented APIs. **Never** put any Javadoc on `@RestController` classes — controllers carry OpenAPI annotations only.

## JEP 467 syntax in one paragraph

Every line of a Markdown Javadoc comment starts with `///`. The body is CommonMark: paragraphs separated by blank `///` lines, `**bold**`, `*italic*`, `[link text](URL)`, fenced code blocks, and lists all work. Standard Javadoc tags (`@param`, `@return`, `@throws`, `@since`, `@see`) are recognized inside the `///` block and behave as in traditional Javadoc — but the description content around them is Markdown.

## Class-level Javadoc structure

```
/// Summary line — one sentence, ends with a period, ≤ 120 chars.
///
/// Description block in Markdown. State purpose, bounded responsibility, and
/// what this class does **not** own. Reference collaborators with
/// {@link OtherType} when navigation aids comprehension. Lists and code blocks
/// are valid:
///
/// - bullet one
/// - bullet two
///
/// @since 1.0
public class SomeService { … }
```

Rules:

- **Summary line**: first sentence. Must end with `.` (Javadoc's parser splits there). Keep ≤ 120 chars; IDEs display this in summaries.
- **Blank `///` line**: separates summary from description. Required.
- **Description block**: free CommonMark. State responsibility and explicit non-responsibilities (what this class delegates to or does not own).
- **Tags**: only those listed below. No `@author`, no `@version` (Git owns history), no `@deprecated` unless the type is actually annotated `@Deprecated`.

## Method-level tags

| Tag | When required | What it must contain | Fragment example |
|---|---|---|---|
| `@param` | Every parameter, in declaration order. | What the parameter *means* in the domain, not its type. Note constraints (positive, non-blank, non-null). | `/// @param id the unique book identifier; must be positive` |
| `@return` | Every non-void method. | The shape of the returned value, nullability guarantees, ordering guarantees, emptiness semantics. | ``/// @return the book payload, or `Optional.empty()` if no book matches`` |
| `@throws` | Every checked exception, plus every unchecked exception the caller must handle (typically those that map to HTTP error responses). | The condition that fires it. For service methods called by controllers, note which `@ApiResponse` status code on the controller it maps to. | `/// @throws BookNotFoundException if no book exists with the given id (maps to 404 on the controller)` |
| `@since` | First introduction of a public type or method. | A version, release, or date — whatever the project uses. Helps agents distinguish new from legacy API. | `/// @since 1.0` |
| `@see` | When a closely related type is non-obvious from the code. Use sparingly. | A `{@link}`-style reference or class name. | `/// @see LoanService` |

## Markdown techniques that pay off in JEP 467 Javadoc

- **Fenced code blocks** for usage examples:

  ````
  /// Usage:
  /// ```java
  /// BookResponse book = bookService.findById(42L);
  /// ```
  ````

- **Inline code** with backticks: `` `Optional.empty()` ``, `` `@Transactional(readOnly = true)` ``.
- **Lists** for preconditions / postconditions:

  ```
  /// Preconditions:
  ///
  /// - the caller holds a valid bearer token
  /// - `id` is positive
  ```

- **Links** to JIRA tickets, ADRs, or related docs: `[ADR-007](https://internal/adr/007)`.
- **Strong emphasis** for "Idempotent", "Not idempotent", "Read-only", "Publishes event": `**Idempotent**`.

## What NOT to use

- `@author` — Git history is authoritative.
- `@version` — managed by build tooling, not source comments.
- `@deprecated` Javadoc tag without the `@Deprecated` annotation — keep them paired or omit both.
- Plain `/** ... */` Javadoc on documented public API — JEP 467 `///` is the standard for this project.
- Empty Javadoc skeletons generated by IDEs (`/// @param id`). Either document the parameter meaningfully or omit the comment.
- "What" narration ("Returns the book.") on getters — the signature already says that. Add Javadoc only when there is *intent* worth recording.
- **Any** Javadoc on `@RestController` classes — controllers express their contract through OpenAPI annotations exclusively.

## Cross-layer alignment recap

- A controller's `@ApiResponse(responseCode = "404")` must correspond to a service method's `@throws BookNotFoundException`.
- A controller's `@Operation.description` Markdown can reference the service method (`{@link BookService#findById}` syntax inside an OpenAPI description is not auto-linked, but writing `BookService.findById(Long)` in plain text helps both humans and agents navigate).
- Service Javadoc carries the *full* semantic contract; the controller's `@Operation.description` carries the HTTP-layer summary of that contract.
